# คู่มือ AILE POS Cloud v1.4 — ขายออฟไลน์และเครื่องพิมพ์

> **รุ่นพัฒนา (Development Preview)** ไม่ได้ผ่านการตรวจสอบการใช้งานหลายเครื่องกับ PostgreSQL หรือเครื่องพิมพ์จริง ห้ามใช้เป็นระบบรับชำระทางการเงินอย่างเป็นทางการก่อนทดสอบหน้างาน

## 1) Offline Mode คืออะไร

- เปิดเว็บผ่าน **http://localhost:4000** หรือ HTTPS อย่างน้อยครั้งหนึ่ง ขณะออนไลน์ เพื่อให้ Service Worker แคชไฟล์โปรแกรม.
- หลัง **เข้าสู่ระบบ API แล้วและโหลดสินค้า/สต็อกสำเร็จ** ระบบเก็บ snapshot สินค้าและสต็อกของ Tenant/Branch ไว้ใน IndexedDB. ไม่เก็บรหัสผ่านหรือ Token ลงใน IndexedDB.
- ถ้าเน็ตหลุดขณะหน้าพนักงานเปิดอยู่ สามารถสร้าง *รายการขายเงินสดรอซิงก์* ได้. ระบบบันทึกคำขอพร้อม Idempotency Key ลง IndexedDB **ก่อน** เรียก API. หากตอบกลับไม่แน่ชัด ระบบส่งคำขอเดิมเมื่อออนไลน์ เพื่อป้องกันบิลซ้ำ.
- บิลที่รอซิงก์ **ยังไม่ใช่รายการขายสำเร็จในระบบกลาง**; ไม่แสดงเป็นยอดขายยืนยัน ไม่ตัดสต็อก PostgreSQL ไม่ส่ง KDS ข้ามเครื่อง และไม่ออกใบกำกับภาษี. หากกะปิด สต็อกหมด Auth หมดอายุ หรือข้อผิดพลาดตรวจสอบอื่น API อาจปฏิเสธและแสดงรายการ `ต้องตรวจสอบ`.
- เมนู **ออฟไลน์ / ซิงก์** แสดงจำนวนค้าง สถานะการซิงก์ รายการที่ติดปัญหา และปุ่มลองใหม่หลังตรวจสอบ. ลบคิวได้เมื่อผู้จัดการยืนยันกับเซิร์ฟเวอร์ว่าธุรกรรมไม่ถูกบันทึกไปก่อนแล้วเท่านั้น.
- ต้องใช้ **เบราว์เซอร์ โปรไฟล์ และเครื่องเดิม** ไม่เปิด Private/Incognito และไม่เคลียร์ข้อมูลเว็บไซต์ก่อนซิงก์. ข้อมูลออฟไลน์ไม่ได้แชร์ข้ามเครื่อง. ยังไม่มี local LAN server ที่รับรายการข้ามเครื่องขณะ WAN ล่ม.
- ไม่รองรับ QR/บัตรชำระเงินจริงขณะออฟไลน์, บุฟเฟ่พร้อมคิวสั่งข้ามเครื่อง, แก้บิลและคืนเงินออฟไลน์. การพิมพ์เอกสารยืนยันจะทำหลังซิงก์สำเร็จเท่านั้น.

## 2) ตั้งค่าเครื่องพิมพ์

เลือกเมนู Sidebar: **เครื่องพิมพ์ / เอกสาร**

ตั้งค่าต่อสาขาได้ถึง 12 โปรไฟล์ในรุ่นนี้:
- เปิด/ปิดอุปกรณ์พิมพ์, เปิด/ปิดพิมพ์อัตโนมัติ (ค่าเริ่มต้น `ปิด`)
- ประเภทงาน: ใบเสร็จ, ใบสั่งครัว, ใบกำกับภาษีฉบับร่าง
- กระดาษ 58 มม., 80 มม., A4, A5 หรือความกว้างที่กำหนดเอง 40–300 มม.
- จำนวนพิมพ์ 1–10 ชุด, ขอบกระดาษ, ขนาดตัวอักษร, ข้อมูลร้าน
- ครัว: พิมพ์ทั้งหมด, โซนครัวอาหาร, บาร์เครื่องดื่ม (อาศัยหมวดสินค้าที่ตั้งไว้)

### วิธีที่แนะนำ: Browser / Driver

ติดตั้งเครื่องพิมพ์เข้าระบบ Windows/macOS/Linux ตามผู้ผลิต ไม่ว่าจะเชื่อม USB, Wi-Fi หรือ LAN. เลือก `Browser / Driver` แล้วกด **พิมพ์ทดสอบ**. เบราว์เซอร์จะเปิดหน้าต่างพิมพ์ให้เลือกเครื่องและกระดาษ. ขนาด `@page` ขึ้นกับการรองรับของไดรเวอร์และเบราว์เซอร์; บางเครื่องต้องกำหนด Roll Size ใน Printer Preferences ด้วย. ทดสอบการตัดกระดาษจริงก่อนใช้งาน.

### ตัวเลือกขั้นสูง: LAN/Wi‑Fi direct หรือ USB/OS Queue ผ่าน Local Print Bridge

รันโปรเซสนี้บน **เครื่องแคชเชียร์** ไม่ใช่บนเซิร์ฟเวอร์สาธารณะ:

```powershell
# Windows PowerShell: ระบุชื่อคิวที่ติดตั้งใน Windows ก่อน
$env:AILE_PRINTER_QUEUES = "POS80,KITCHEN"
npm run print:bridge
```

Bridge รันที่ `http://127.0.0.1:17654` เท่านั้น และพิมพ์คีย์เฉพาะรอบการรันใน Terminal. นำคีย์นี้ไปกรอกในหน้า **เครื่องพิมพ์ / เอกสาร** แล้วเลือก `LAN/Wi-Fi Bridge` (กำหนด IP ภายในและพอร์ต 9100) หรือ `USB/OS Queue Bridge` (กำหนดชื่อคิวที่อยู่ใน allowlist). การพิมพ์ซ้ำหลายชุดใช้จำนวนชุดในโปรไฟล์.

> **ภาษาไทย:** การยิง ESC/POS ดิบผ่าน TCP อาจพิมพ์ภาษาไทยไม่ถูกต้อง เพราะ code page แต่ละยี่ห้อต่างกัน. รุ่นนี้ **ยังไม่มีระบบแปลงข้อความเป็นภาพ Raster ESC/POS ภาษาไทย**. ให้ใช้ Browser/OS Driver หากต้องการภาษาไทยถูกต้อง. Bridge ใช้ Auth Key, allowlist Origin, bind loopback และจำกัด IP RFC1918/port 9100 เท่านั้น แต่ยังต้องประเมินความปลอดภัยในสภาพแวดล้อมจริง.

## 3) ใบกำกับภาษี

v1.4 มี **แม่แบบร่าง** สำหรับจัดหน้า A4/80 มม. และระบุข้อมูลผู้ขาย เพื่อดูตัวอย่างและทดลองพิมพ์. **ยังไม่ใช่ระบบออกใบกำกับภาษีแบบถูกต้องครบตามกฎหมาย**. ระบบยังไม่มีข้อมูลผู้ซื้อครบถ้วน, เลขที่เอกสารเรียงตามข้อกำหนด, วิธีคำนวณ VAT ตามประเภทธุรกิจ, การยกเลิกเอกสาร/ใบลดหนี้ หรือบริการ e-Tax Invoice/e-Receipt ที่ได้รับการรับรอง. ต้องตรวจสอบข้อกำหนดล่าสุดกับกรมสรรพากรหรือผู้เชี่ยวชาญก่อนใช้งานจริง.

## 4) ทดสอบ/รัน

```powershell
Copy-Item .env.example .env
# ตั้ง JWT_SECRET ใน .env
# Docker Desktop / Node.js 20+ ต้องติดตั้งและเริ่มบริการแล้ว
docker compose up -d
npm install
npm run db:init
npm run check
npm test
npm start
```

เปิด `http://localhost:4000` → เข้าสู่ระบบ API → ลองเพิ่มสินค้า / เปิดกะ / ขายเงินสด. ทดสอบปิดอินเทอร์เน็ตด้วยการจำลองผ่าน DevTools ในเบราว์เซอร์ทั่วไป แล้วตรวจคิวในเมนู **ออฟไลน์ / ซิงก์**. ระวัง `localhost`/LAN กับ WAN ไม่เหมือนกัน: ถ้าปิด Wi-Fi ทั้งเครื่องจะเชื่อม backend ที่อยู่เครื่องอื่นไม่ได้ แม้ Service Worker เปิด UI ได้.

**สำคัญ:** ไม่สามารถยืนยันการพิมพ์กับเครื่องจริงในสภาพแวดล้อมนี้ได้ และยังไม่ได้ทดสอบวงจร PostgreSQL จริง. ควรทำ Pilot รวม KDS, เครื่องพิมพ์, คิวออฟไลน์, สต็อกซ้ำข้ามอุปกรณ์ และการกู้คืนข้อมูลก่อนเปิดธุรกิจจริง.

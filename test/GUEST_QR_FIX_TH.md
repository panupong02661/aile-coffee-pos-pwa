# AILE POS Cloud v1.7 — แก้ Guest QR ไม่เห็นเมนู/โต๊ะ

## เหตุผลที่ v1.6 เปิดโต๊ะแล้ว Guest ยังไม่เห็น

หน้า Standalone POS และ Standalone Guest เมื่อเปิดแยกใน ChatGPT Preview อาจได้รับ origin / sandbox / พื้นที่ `localStorage` คนละแห่ง โค้ด Guest รุ่นเดิมอ่าน `aile_pos_v2_demo` จากพื้นที่ของตัวเอง จึงหา `diningTabs` ของ POS ไม่เจอ แม้ POS เปิด T01 แล้ว การเปิดหน้าใหม่หรือรีเฟรชไม่สามารถแก้การแยก origin นี้ได้

## สิ่งที่เปลี่ยนใน v1.7

1. **QR Ordering → ทดลองสั่งโต๊ะนี้ใน POS**: เปิด Guest ผ่าน iframe ซึ่งใช้ origin/ข้อมูลเดียวกับ POS เดียวกัน (Demo) สินค้า, สต็อก, โต๊ะ, ครัว และยอดค้างชำระเชื่อมกันในเบราว์เซอร์นั้น
2. **Guest Standalone เปิดโดยตรง**: หากไม่มีข้อมูลโต๊ะที่เปิดอยู่ จะเริ่มโต๊ะ T01 พร้อมสินค้า Demo ให้เลือกและสั่งได้ทันที แสดงชัดว่าออเดอร์นี้ *ไม่* ส่งไป POS ที่อยู่คนละ origin
3. **QR โหมด API จริง**: ใช้ `GET /api/guest/:token` และ `POST /api/guest/:token/orders` กับ PostgreSQL และ secure token ตามเดิม ไม่ใช้ `localStorage` หรือข้อมูล Demo สำหรับร้านจริง
4. **แก้โหมดบริการ**: โต๊ะคาเฟ่/ร้านอาหารไม่ถูกผูก `plan` ของบุฟเฟ่โดยไม่จำเป็น และ Guest ไม่แสดงชื่อแพ็กเกจหากไม่ได้เปิดโหมดบุฟเฟ่
5. เพิ่ม smoke tests และชุดทดสอบ guest demo ใหม่

## วิธีทดลองในไฟล์ HTML ภายในแชต

1. เปิด `AILE_POS_Cloud_v1.7_Standalone.html`
2. ไปที่ **ออเดอร์โต๊ะ** → เลือก T01 → เลือก **คาเฟ่** → **เปิดโต๊ะและไป POS**
3. ไป **QR Ordering** ใน Sidebar → กด **ทดลองสั่ง T01** (แถบสีเขียว)
4. หน้า Guest เปิด **ภายใน POS** ให้เลือกชาไทยหรือสินค้าอื่น → **ตรวจสอบและสั่งอาหาร** → **ยืนยันส่งเข้าครัว**
5. กด **จอครัว** ด้านบนของหน้าทดลอง → เห็นคิวใหม่ แล้วกลับไปที่โต๊ะ T01 เพื่อดูรายการค้าง

การทดลองนี้ไม่ต้องสแกน QR และไม่ต้องติดตั้ง Docker แต่เก็บข้อมูลในเบราว์เซอร์เท่านั้น

**หากเปิด `AILE_POS_Cloud_v1.7_Guest.html` ตรง ๆ:** หน้าเว็บจะมีเมนูและโต๊ะตัวอย่าง T01 ทันที ออเดอร์ที่กดในหน้านี้เป็น Demo ของหน้า Guest เอง ไม่ใช่ออเดอร์ของไฟล์ POS ที่เปิดอยู่คนละ sandbox

## วิธีให้มือถือจริงสแกน QR และส่งเข้าร้านจริง

สำหรับการใช้งานหลายเครื่อง ต้องมี Backend ที่ใช้งานจริงและฐานข้อมูลกลาง ไม่ใช้ Standalone HTML จากแชต

1. ติดตั้ง Node.js 20+ และ Docker Desktop บนเครื่องเซิร์ฟเวอร์ จากนั้นเปิดโปรเจกต์ v1.7
2. ตั้ง `.env` และ `JWT_SECRET` ที่สุ่มอย่างปลอดภัย (อย่างน้อย 32 ตัวอักษร) และตรวจสอบสิทธิ์เครือข่าย
3. สั่ง `docker compose up -d`, `npm install`, `npm run db:init`, `npm start`
4. เปิดเว็บ POS จาก URL ที่โทรศัพท์เข้าถึงได้ (เช่นโดเมน HTTPS ของร้าน) **อย่าใช้** `localhost` ของพนักงานเพื่อทำ QR สำหรับมือถือ
5. เข้าสู่ระบบ API, เลือกสาขา, เปิดโต๊ะ และสร้าง QR โหมด API; QR จะมีโทเคนแบบหมดอายุและเพิกถอนได้
6. สแกนด้วยมือถือที่เข้าถึงโดเมนเดียวกัน → Guest จะโหลดเมนูผ่าน Backend โดยไม่อ่าน localStorage ของ POS

ใน LAN อาจเข้าผ่าน IP ของเครื่องเซิร์ฟเวอร์ได้ถ้ามี firewall/เครือข่ายรองรับ แต่แนะนำ HTTPS โดยเฉพาะถ้านำข้อมูลลูกค้าออกสู่อินเทอร์เน็ต โทรศัพท์ต้องไม่ใช้ `file://` และไม่ใช้โดเมนพรีวิวชั่วคราวของ ChatGPT

## สถานะทดสอบ

- `npm run check`: ตรวจ Syntax ผ่าน
- `npm test`: Node Unit Tests ผ่าน 26/26
- `python tests/v17_browser_smoke.py`: Chromium ผ่านการเปิดโต๊ะคาเฟ่ → เปิด Guest ใน POS → ส่งออเดอร์ → เข้า KDS → ยอดสินค้า/สต็อกอัปเดต
- Guest Standalone: Chromium ผ่านแสดงเมนูตัวอย่างและส่งคิวทดลอง
- **ยังไม่ทดสอบครบวงจร PostgreSQL, QR ข้ามมือถือในเครือข่ายจริง, Payment Gateway และอุปกรณ์จริง** ไม่ควรนำไปใช้รับเงินโดยไม่ผ่านการทดสอบเหล่านี้

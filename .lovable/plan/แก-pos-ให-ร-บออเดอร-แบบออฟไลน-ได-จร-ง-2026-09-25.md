# แก้ POS ให้รับออเดอร์แบบออฟไลน์ได้จริง

## สาเหตุที่ยืนยันแล้ว
- หน้าชำระเงินจริงใน `PaymentModal` บันทึกตรงไปยัง Supabase และรอผลจากอินเทอร์เน็ต จึงแสดง `TypeError: Load failed` เมื่อปิดเน็ต
- แม้มีระบบคิวออฟไลน์ใน `useOfflinePOS` อยู่แล้ว แต่หน้า POS ดึงมาใช้เฉพาะเมนูสำรองและสถานะออนไลน์ ไม่ได้ส่งการชำระเงินเข้า `saveOrder`
- ระบบเขียนออเดอร์ลงเครื่องปัจจุบันกลืนข้อผิดพลาดการบันทึก ทำให้มีโอกาสแจ้งว่าสำเร็จทั้งที่ข้อมูลไม่ได้เก็บจริง
- Background Sync ใน Service Worker ยังเป็นโครงเปล่า การซิงก์จริงจึงต้องอาศัยหน้าร้านเปิดอยู่และ hook ทำงาน

## สิ่งที่จะทำ
1. **รวมเส้นทางบันทึกออเดอร์**
   - ให้หน้าชำระเงินใช้ตัวบันทึกกลางเพียงทางเดียว ทั้งมือถือ แท็บเล็ต และคอมพิวเตอร์
   - เมื่อออฟไลน์หรือ Supabase ติดต่อไม่ได้ ให้บันทึกออเดอร์และรายการสินค้าลงเครื่องก่อน แล้วถือว่าการขายสำเร็จ
   - เก็บข้อมูลสำคัญครบ เช่น สาขา เลขออเดอร์ ประเภทออเดอร์ วิธีชำระ ส่วนลด สมาชิก Add-on วันที่ย้อนหลัง และรายการสินค้า

2. **ทำคิวออฟไลน์ให้เชื่อถือได้**
   - ยืนยันว่าการเขียนลงเครื่องสำเร็จก่อนล้างตะกร้าและแสดงข้อความสำเร็จ
   - ถ้าพื้นที่จัดเก็บใช้ไม่ได้ ให้คงตะกร้าไว้และแจ้งข้อผิดพลาดชัดเจน ไม่ทำเหมือนบันทึกสำเร็จ
   - แยกคิวตามบัญชีและสาขาเดิม เพื่อไม่ให้ออเดอร์ข้ามร้าน

3. **ซิงก์กลับโดยไม่สร้างออเดอร์ซ้ำ**
   - เมื่ออินเทอร์เน็ตกลับมา ให้ซิงก์อัตโนมัติและมีปุ่มซิงก์เดิมสำหรับสั่งซ้ำได้
   - ใช้เลขออเดอร์เป็นตัวตรวจซ้ำ; ถ้าบันทึกหัวออเดอร์สำเร็จแต่รายการสินค้าขาด ให้เติมเฉพาะส่วนที่ยังไม่ครบแทนการสร้างหัวออเดอร์ใหม่
   - ทำงานต่อทีละออเดอร์ หากรายการหนึ่งล้มเหลว และคงเฉพาะรายการที่ยังไม่สำเร็จในคิว

4. **ทำงานหลังการขายในเวลาที่ถูกต้อง**
   - ขณะออฟไลน์ งดงานที่ต้องใช้เซิร์ฟเวอร์ เช่น แจ้งเตือน ตัดสต็อก แต้มสมาชิก คิว และ WiFi voucher
   - หลังซิงก์ออเดอร์สำเร็จ จึงเรียกงานเหล่านี้แบบไม่ขวางการขาย พร้อมป้องกันการทำซ้ำ
   - หน้าจอแสดง “บันทึกออฟไลน์แล้ว / รอซิงก์” และจำนวนออเดอร์ค้างอย่างถูกต้อง

5. **รองรับการเปิดแอปขณะไม่มีเน็ต**
   - ตรวจ cache ของตัวแอปและเมนูสาขาปัจจุบัน ให้ POS ที่เคยเปิดออนไลน์แล้วกลับมาเปิดและขายต่อได้เมื่อไม่มีอินเทอร์เน็ต
   - ตัดโค้ด Background Sync แบบจำลองที่ไม่ได้ซิงก์จริง หรือเชื่อมให้ใช้คิวเดียวกับ POS เพื่อไม่ให้มีระบบซ้ำซ้อน

## การทดสอบ
- เปิด POS ออนไลน์ให้ข้อมูลสาขาถูกเก็บ จากนั้นปิดอินเทอร์เน็ตและชำระเงินสด/PromptPay/ผสม
- ยืนยันว่าไม่ขึ้น `Load failed`, ตะกร้าถูกล้างเฉพาะหลังเก็บลงเครื่องสำเร็จ และจำนวน “รอซิงก์” เพิ่มขึ้น
- ปิดและเปิดแอปใหม่ขณะยังออฟไลน์ ยืนยันว่าเมนูและคิวออเดอร์ยังอยู่
- เปิดอินเทอร์เน็ตกลับมา ยืนยันว่าออเดอร์ รายการสินค้า และงานหลังการขายเข้าระบบครบเพียงครั้งเดียว
- ทดสอบสลับสองสาขาเพื่อยืนยันว่าคิวและข้อมูลไม่ปะปนกัน
- ตรวจทั้ง iPhone PWA, Android PWA และหน้าจอแท็บเล็ต/คอมพิวเตอร์ พร้อมตรวจ build และ error logs

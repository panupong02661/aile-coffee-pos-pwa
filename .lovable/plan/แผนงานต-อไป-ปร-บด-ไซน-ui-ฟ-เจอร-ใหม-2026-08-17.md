# แผนงานต่อไป: ปรับดีไซน์ UI + ฟีเจอร์ใหม่

## ส่วนที่ 1 — ปรับดีไซน์ให้ทั้งระบบเป็นแนวเดียวกับ POS v2

ตอนนี้ POS หน้าหลักถูกอัปเป็นดีไซน์ใหม่แล้ว แต่หน้าอื่นยังเป็นสไตล์เก่า
(หน้าแดชบอร์ดยังใช้สีตายตัว `bg-cream-50` / `text-coffee-600` และใช้วงกลมหมุนตอนโหลด
แทน Skeleton) ทำให้เปิดสลับหน้าแล้วรู้สึกคนละแอป

จะไล่ปรับตามลำดับความถี่การใช้งาน:

1. **แดชบอร์ด** — การ์ดสถิติแบบใหม่ (ตัวเลขใหญ่ + ไอคอนวงกลม + แถบไล่สี),
   กราฟใส่กรอบการ์ดโทนเดียวกับ POS, เปลี่ยนตัวโหลดเป็น Skeleton
2. **หน้ารายงาน / รายงานขั้นสูง** — แถบตัวกรอง (เดือน/ปี/ช่วงวันที่) จัดใหม่ให้อยู่แถวเดียว
   สะอาดขึ้น, ปุ่มดาวน์โหลด Excel ทั้ง 2 ปุ่มจัดกลุ่ม, ตารางอ่านง่ายบนแท็บเล็ต
3. **หน้าตั้งค่า** — จัดกลุ่มการตั้งค่าเป็นการ์ดหัวข้อ พร้อมไอคอน แทนแท็บยาว ๆ
4. **หน้าสมาชิก / สต็อก / ครัว (KDS)** — ปรับการ์ดและปุ่มให้ขนาดนิ้วกดง่าย
   ใช้โทนสีเดียวกันทั้งหมด

หลักการ: ใช้ semantic token (`--primary`, `--card`, `--muted`) ทั้งหมด ไม่ฝังสีดิบ
เพื่อให้โหมดมืดและธีมทั้ง 8 แบบยังทำงานถูกต้อง

## ส่วนที่ 2 — ฟีเจอร์ใหม่ที่แนะนำ

เรียงตามผลกระทบต่อการใช้งานจริงหน้าร้าน:

1. **สรุปกะ / ปิดรอบขาย (Shift Close)** — สรุปยอดเงินสด, พร้อมเพย์, จำนวนบิล,
   เงินในลิ้นชักตอนเปิด-ปิด พร้อมพิมพ์ใบสรุปกะ
2. **ค้นหาแบบสั่งการ (Command Palette)** — กด/แตะแล้วพิมพ์ชื่อเมนู ชื่อหน้า
   หรือเลขบิล เพื่อกระโดดไปได้ทันที ลดการไล่กดเมนู
3. **โหมดขายด่วน (Quick Sale)** — ปุ่มเมนูขายดี 8 อันดับแรกไว้แถวบนสุดของ POS
   คำนวณอัตโนมัติจากยอดขาย 7 วันล่าสุด
4. **แจ้งเตือนสต็อกใกล้หมดบนหน้า POS** — แสดงป้ายเตือนที่เมนูที่วัตถุดิบใกล้หมด
   ก่อนที่จะขายแล้วติดลบ

## หมายเหตุทางเทคนิค

- งานส่วนที่ 1 เป็นการแก้ชั้นการแสดงผลล้วน ไม่แตะตรรกะการขาย การพิมพ์ หรือฐานข้อมูล
- ฟีเจอร์ "สรุปกะ" ใช้ตาราง `shifts` ที่มีอยู่แล้ว (มี RLS แยกตาม `shop_id` เรียบร้อย)
- ฟีเจอร์อื่นทั้งหมดคำนวณจากข้อมูลออเดอร์เดิม ไม่ต้องสร้างตารางใหม่

## เริ่มจากตรงไหน

แนะนำทำส่วนที่ 1 ข้อ 1–2 (แดชบอร์ด + รายงาน) ก่อน เพราะเป็นหน้าที่เปิดบ่อยรองจาก POS
แล้วค่อยต่อด้วยฟีเจอร์สรุปกะ — บอกได้เลยว่าจะสลับลำดับหรือตัดข้อไหนออก

# ทำให้ทุกบัญชีเข้าสู่ระบบได้ตามปกติ

## อาการที่พบ
หน้าล็อกอินขึ้น "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง" กับทุกบัญชี (admin, manager, kopi) ทั้งที่รหัสผ่านถูกต้อง

## สาเหตุที่ตรวจพบจริง
1. ตัวตรวจสอบบัญชีบนเซิร์ฟเวอร์ (staff-auth) **บูตไม่ขึ้น** — บันทึกของระบบแสดง `module "node:url" not found` และ `UncaughtException` จากไลบรารีที่ถูกดึงมาผิดช่องทาง ทำให้แอปเรียกแล้วได้ "Failed to fetch" ทุกครั้ง
2. บัญชีทั้ง 3 (admin, manager, kopi) ยังไม่มีตัวตนฝั่งเซิร์ฟเวอร์ (คอลัมน์เชื่อมบัญชียังว่างทั้งหมด) จึงต้องพึ่งขั้นตอนเชื่อมอัตโนมัติครั้งแรก ซึ่งตอนนี้ไม่ทำงานเพราะข้อ 1

## สิ่งที่จะทำ
1. แก้วิธีโหลดไลบรารีในตัวตรวจสอบบัญชี ให้บูตได้บน Deno (ใช้ `npm:@supabase/supabase-js@2` แทน `https://esm.sh/...`)
2. ทดสอบเรียกจริงทั้ง 3 บัญชี (admin, manager, kopi) ด้วยรหัสผ่านปัจจุบัน แล้วยืนยันว่าตัวตนเซิร์ฟเวอร์ถูกสร้างและผูกกับบัญชีเดิมสำเร็จ
3. ตรวจว่าเมื่อล็อกอินแล้ว ระบบจับสาขาได้ถูกต้อง (admin เห็นทุกสาขา, manager/kopi เห็นเฉพาะสาขาตัวเอง) และเมนู/สิทธิ์แสดงครบ
4. เพิ่มข้อความแจ้งเตือนที่ตรงจริงบนหน้าล็อกอิน แยก "รหัสผ่านไม่ถูกต้อง" ออกจาก "ติดต่อเซิร์ฟเวอร์ไม่ได้" เพื่อไม่ให้เข้าใจผิดอีก
5. ทดสอบจริงในหน้าตัวอย่างด้วยการเข้าสู่ระบบทีละบัญชี

## หมายเหตุ
- รหัสผ่านเดิมของทุกบัญชีถูกใช้ต่อได้ ไม่ต้องตั้งใหม่
- หากโปรเจกต์ Supabase ปิดการเข้าสู่ระบบแบบอีเมล/รหัสผ่านไว้ ต้องเปิดที่แดชบอร์ด Supabase หนึ่งครั้ง — ผมจะตรวจและแจ้งหากจำเป็น

## รายละเอียดทางเทคนิค
- `supabase/functions/staff-auth/index.ts`: เปลี่ยน import เป็น `npm:@supabase/supabase-js@2`
- คงลอจิกเดิม: ตรวจ `password_hash`/`password_salt`, สร้าง auth user ด้วยอีเมลภายใน `@staff.aile-pos.local`, เขียน `users.auth_user_id`, คืน session
- `src/hooks/useAuth.tsx`: แยกกรณี network/function error ออกจากกรณี credential ผิด

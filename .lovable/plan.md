# แอปที่ติดตั้ง (APK) ล็อกอินไม่ได้

## สาเหตุที่ตรวจพบจริง
APK ที่ติดตั้งในเครื่องเป็นไฟล์เก่า ที่สร้างก่อนย้ายระบบล็อกอินไปตรวจสอบที่เซิร์ฟเวอร์

- แอปเวอร์ชันเก่าเรียกฟังก์ชันตรวจรหัสผ่านตัวเดิม (`authenticate_user`) ตรงจากเครื่องลูกค้า
- ตรวจสิทธิ์จริงในฐานข้อมูลแล้ว: ฟังก์ชันนี้ตอนนี้เปิดให้เฉพาะระบบภายใน (postgres, service_role) เท่านั้น แอปฝั่งเครื่องเรียกไม่ได้อีกแล้ว
- เวอร์ชันเว็บ/พรีวิวเข้าได้ปกติ เพราะใช้เส้นทางใหม่ (staff-auth) ที่ทดสอบผ่านแล้วทั้ง admin, manager, kopi

สรุป: ไม่ใช่รหัสผ่านผิด และไม่ใช่บัญชีถูกล็อก แต่เป็นเพราะแอปในเครื่องยังเป็นโค้ดเก่า

## สิ่งที่จะทำ
1. สร้างไฟล์ APK ใหม่จากโค้ดปัจจุบัน (ที่ใช้ระบบล็อกอินใหม่) ให้พร้อมติดตั้ง
2. เพิ่มการแจ้งเตือนในหน้าล็อกอินของแอป เมื่อพบว่าแอปที่ติดตั้งเป็นเวอร์ชันเก่ากว่าระบบ จะขึ้นข้อความ "แอปเวอร์ชันเก่า กรุณาอัปเดต" แทนข้อความ "รหัสผ่านไม่ถูกต้อง" ที่ทำให้เข้าใจผิด
3. แสดงหมายเลขเวอร์ชันเล็ก ๆ ที่มุมล่างหน้าล็อกอิน เพื่อเช็กได้ทันทีว่าเครื่องไหนยังใช้ของเก่า
4. เขียนขั้นตอนติดตั้งทับของเดิม (ไม่ต้องถอนแอป ข้อมูลและการตั้งค่าเดิมยังอยู่) ไว้ในหน้าคู่มือสร้างแอปในระบบ

## ที่ต้องรู้ก่อนเริ่ม
- การสร้าง APK ต้องทำบนเครื่องคุณเอง (ต้องใช้ Android Studio) ผมเตรียมโค้ดและคำสั่งให้ครบ พร้อมขั้นตอนทีละข้อ
- ถ้าต้องการใช้งานทันทีระหว่างรอทำ APK ใหม่ เปิดผ่านเบราว์เซอร์บนแท็บเล็ต/มือถือแล้วกด "เพิ่มลงหน้าจอโฮม" ใช้ได้เลย เพราะเวอร์ชันเว็บเป็นโค้ดล่าสุดเสมอ

## รายละเอียดทางเทคนิค
- `src/components/LoginPage.tsx`: แยกเคส error ของ edge function `staff-auth` ที่บ่งชี้ client เก่า/RPC ถูกปฏิเสธ (401/403/PGRST202) เป็นข้อความ "แอปเวอร์ชันเก่า" + แสดง `APP_VERSION`
- เพิ่มค่าเวอร์ชันจาก `package.json` / build timestamp ผ่าน `import.meta.env`
- `src/pages/AppBuildGuide.tsx`: เพิ่มหัวข้อ "อัปเดตแอปที่ติดตั้งแล้ว" — `npm run build` → `npx cap sync android` → build APK ใน Android Studio → ติดตั้งทับ (ต้องเป็น keystore เดิม)
- ไม่แก้ฐานข้อมูลและไม่คืนสิทธิ์ `authenticate_user` ให้ anon เพราะเป็นช่องโหว่ที่เพิ่งปิดไป

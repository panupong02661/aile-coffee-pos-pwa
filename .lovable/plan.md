# เพิ่มช่อง Channel Access Token / Channel Secret ในหน้าตั้งค่าการแจ้งเตือน

เป้าหมาย: ให้เปลี่ยนบัญชี LINE OA ได้เองจากหน้าเว็บ แยกตามสาขา และแยกได้ในแต่ละประเภทการแจ้งเตือน (ออเดอร์ออนไลน์ / ออเดอร์ POS / รายงานประจำวัน / รายงานประจำเดือน) โดยไม่ต้องให้ผมไปแก้ค่าลับในระบบหลังบ้านทุกครั้ง

## สิ่งที่ผู้ใช้จะเห็น

ในการ์ด LINE ของแต่ละประเภทการแจ้งเตือน จะมีเพิ่ม:
- ช่อง **Channel Access Token** (ซ่อนค่าเป็นจุด มีปุ่มแสดง/ซ่อน)
- ช่อง **Channel Secret**
- ตัวเลือก **"ใช้บัญชีเดียวกับค่าเริ่มต้นของร้าน"** (ติ๊กไว้ = ใช้บัญชีกลางเหมือนทุกวันนี้ ไม่ต้องกรอกซ้ำ 4 ที่)
- ปุ่ม "ทดสอบ" เดิมจะทดสอบด้วยบัญชีของช่องนั้น ๆ และบอกสาเหตุจริงเมื่อไม่ผ่าน (โทเคนผิด / บอทไม่อยู่ในกลุ่ม / ไม่พบกลุ่ม)

จะมีการ์ด "บัญชี LINE เริ่มต้นของร้าน" หนึ่งชุดไว้ด้านบน สำหรับกรอกบัญชีกลางของสาขานั้น

## ความปลอดภัย (สำคัญ)

Channel Access Token คือกุญแจส่งข้อความในนามร้าน ถ้าเก็บรวมไว้ในตารางตั้งค่าเดิมที่หน้าเว็บอ่านได้ตรง ๆ จะเสี่ยงรั่ว จึงจะเก็บไว้ในตารางแยกที่ฝั่งหน้าเว็บ **อ่านค่าเต็มไม่ได้** อ่านได้แค่ "ตั้งค่าไว้แล้วหรือยัง" และ 4 ตัวท้าย ส่วนการบันทึกและการใช้งานจริงทำผ่านฝั่งเซิร์ฟเวอร์เท่านั้น

## รายละเอียดทางเทคนิค

1. ตารางใหม่ `public.line_channel_credentials`
   - `id`, `shop_id`, `scope` (`default` | `online_orders` | `pos_orders` | `daily_reports` | `monthly_reports`), `channel_access_token`, `channel_secret`, `updated_at`, unique (`shop_id`, `scope`)
   - GRANT ให้ `service_role` เท่านั้น (ไม่ให้ `anon`/`authenticated`), เปิด RLS โดยไม่มี policy สำหรับ client
2. Edge function ใหม่ `line-credentials`
   - `list` → คืนเฉพาะ `{ scope, configured, tokenLast4, secretConfigured }` ตาม `shop_id`
   - `save` / `clear` → เขียน/ลบค่าของ `shop_id` + `scope`
3. ตัวช่วยฝั่งเซิร์ฟเวอร์ `resolveLineCredentials(shopId, scope)` ใช้ร่วมกันใน `line-messaging`, `send-order-notification`, `send-daily-report`
   - ลำดับการเลือก: credential ของ scope นั้น → credential `default` ของร้าน → ค่าลับกลาง `LINE_CHANNEL_ACCESS_TOKEN` (ของเดิม ยังใช้ได้)
   - ทุก call ที่เรียกจากหน้าเว็บส่ง `shopId` และ `scope` ไปด้วย
4. `src/pages/NotificationPage.tsx`
   - โหลดสถานะ credential ผ่าน `line-credentials` หลัง `shopId` พร้อม (ตามกติกา multi-tenant เดิม)
   - เพิ่ม UI ต่อการ์ด LINE ทั้ง 4 ประเภท + การ์ดบัญชีเริ่มต้น, บันทึกแยกจากปุ่มบันทึกรวม (บันทึกทันทีเมื่อกด "บันทึกบัญชี")
   - ส่ง `scope` ไปกับ `verifyTarget` และการทดสอบส่งข้อความ
5. ไม่แตะ RLS เดิมของ `notification_settings` และไม่ดึงข้อมูลข้ามสาขา

## ผลกระทบ

- ร้านที่ยังไม่กรอกอะไรเลย จะยังใช้บัญชี LINE เดิมของระบบต่อไป ไม่มีอะไรเปลี่ยน
- เมื่อกรอกบัญชีของร้าน/ของประเภทใดแล้ว การแจ้งเตือนนั้นจะส่งจากบัญชีนั้นทันที
- Group ID ต้องเป็นกลุ่มที่บอทของบัญชีนั้นอยู่ด้วย ไม่งั้นจะขึ้น "ไม่พบกลุ่ม" เหมือนเดิม
